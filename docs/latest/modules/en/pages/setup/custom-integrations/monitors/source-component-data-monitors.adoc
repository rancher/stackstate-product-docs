= Source Component Data Monitors
:description: Judge the health of components from the data their source sent, such as a Kubernetes object, with CEL expressions in the source-component-data monitor function
:page-languages: [en]
:revdate: 2026-11-10
:page-revdate: {revdate}

== Overview

The source component data monitor function decides the health of a component from the data the component was synchronized with: for a Kubernetes component, the Kubernetes object that the agent or the OpenTelemetry collector sent. You write the decision as https://cel.dev[CEL] expressions, so this kind of monitor needs no scripting.

NOTE: This function requires SUSE Observability {next-release-version} or later.

Use it for health that can be read from a single component's own data, such as a Pod's phase and container statuses or a Node's `spec.unschedulable` flag. For health based on metrics, use a threshold monitor instead.

== How a monitor is evaluated

On every run, the monitor evaluates each component that its `query` selects in three steps:

. *Choose the source.* A component can be merged from several sources, for example from both the cluster agent and the OpenTelemetry collector. `sourceSelector` is evaluated for each source, and the first source that matches is used. Sources are ordered by type and then by identifier, so the choice is the same on every run. A component without a matching source reports `UNKNOWN` with reason `NoMatchingSource`.
. *Judge the source.* `selector` returns the results for the source: a map for a single health state, or a list of maps for one health state per item, for example per container. If `selector` returns an empty list, the monitor reports the `whenEmpty` result, which is `{"health": "CLEAR"}` by default.
. *Report errors as `UNKNOWN`.* If an expression fails, for example because it reads a field the data does not contain, the component reports `UNKNOWN` with the error as reason. Missing data never results in `CLEAR`.

== Arguments

[cols="1,1,3"]
|===
|Argument |Type |Description

|`query`
|STQL query, required
|The components to monitor, for example `type = "pod"`.

|`sourceSelector`
|CEL, boolean, required
|Selects the source to judge, for example `source.topologySync.identifier.startsWith("urn:stackpack:kubernetes-v2:")` for the data of the Kubernetes StackPack's Sync.

|`selector`
|CEL, map or list, required
|The results for the source.

|`whenEmpty`
|CEL, map
|The result when `selector` returns an empty list. Defaults to `{"health": "CLEAR"}`.
|===

Each result is a map with these fields:

[cols="1,3"]
|===
|Field |Description

|`health`
|Required. `CLEAR`, `DEVIATING`, `CRITICAL` or `UNKNOWN`.

|`title`
|The title of the health state. Defaults to the monitor's name.

|`reason`
|A short explanation of the health state.

|`data`
|Data for the remediation hint.

|`key`
|Identifies the health state among the component's results. Set it when a list of results can change in length or order, for example to the container name, so that each health state keeps its identity.
|===

== CEL context

The expressions can read the following variables:

[cols="1,3"]
|===
|Variable |Contents

|`name`
|The component's name.

|`source.identifier`
|The identifier of the source.

|`source.tags`
|The source's tags, mapping each tag key to its list of values, for example `source.tags["cluster-name"][0]`.

|`source.configuration`
|The source's data, for a Kubernetes object its `apiVersion`, `kind`, `metadata` and `spec`. The cluster agent does not always send `kind`.

|`source.status`
|The status of the source, for a Kubernetes object its `status`, regardless of which producer sent it.

|`source.topologySync.identifier`, `source.topologySync.name`
|The identifier and name of the Sync that synchronized the source, empty for other sources.

|`source.mapping.identifier`, `source.mapping.name`
|The identifier and name of the OpenTelemetry component mapping that created the source, empty for other sources.

|`now`
|The time of the evaluation, for example `timestamp(source.configuration.metadata.creationTimestamp) < now - duration("15m")`.
|===

Besides the standard CEL functions and macros, the expressions can use the string functions, `cel.bind(name, value, expression)` to name an intermediate value, and optional field selection, such as `source.status.?phase.orValue("")`.

TIP: To select through several fields that may be missing, unwrap each level: `c.?state.orValue({}).?waiting.orValue({}).?reason.orValue("")`. A chained `c.?state.?waiting` does not give the expected result.

== Remediation hint data

The remediation hint of every health state receives the same fields:

* `componentName`, the component's name.
* `componentUrnForUrl`, the component's identifier, encoded for use in a link.
* `sourceIdentifier`, the identifier of the source that was judged, empty when no source matched.
* `reason`, the result's reason, empty when it has none.
* `data`, the result's data, empty when it has none.

A remediation hint template fails to render when it reads a top-level field that is missing, but fields inside `data` may be missing. Use `{{#if data.reasons.CrashLoopBackOff}}` to show a section only for some results.

== Example

This monitor reports a `CRITICAL` health state for each container of a Pod that is waiting with an error, and `UNKNOWN` for a Pod without status:

----
  - _type: "Monitor"
    name: "Pods in Waiting State"
    tags:
      - pods
      - containers
    function: "urn:stackpack:common:monitor-function:source-component-data"
    identifier: "urn:stackpack:my-stackpack:monitor:pods-in-waiting-state"
    status: "ENABLED"
    description: "Reports containers that are waiting with an error."
    arguments:
      query: 'type = "pod"'
      sourceSelector: 'source.topologySync.identifier.startsWith("urn:stackpack:kubernetes-v2:")'
      selector: |-
        !source.status.?phase.hasValue()
          ? [{"health": "UNKNOWN", "title": "Pod Waiting State", "reason": "Pod status is missing"}]
          : source.status.?containerStatuses.orValue([])
              .filter(c, !c.?state.orValue({}).?running.hasValue() &&
                c.?state.orValue({}).?waiting.orValue({}).?reason.orValue("") in ["CrashLoopBackOff", "ImagePullBackOff"])
              .map(c, {"health": "CRITICAL", "title": "Pod Waiting State (" + c.name + ": " + c.state.waiting.reason + ")",
                "reason": c.state.waiting.?message.orValue(c.state.waiting.reason), "key": c.name,
                "data": {"container": c, "reasons": {c.state.waiting.reason: true}}})
      whenEmpty: '{"health": "CLEAR", "title": "Pod Waiting State"}'
    intervalSeconds: 30
    remediationHint: "Inspect the events of [this Pod](/#/components/{{ componentUrnForUrl }}){{#if data.reasons.CrashLoopBackOff}} and the logs of container `{{ data.container.name }}`{{/if}}."
----

* `sourceSelector` selects the data the Kubernetes StackPack's Sync sent, not data that other producers merged into the component.
* `selector` returns a list with one result per waiting container, keyed on the container's name, and a one-item list for a Pod without status.
* `whenEmpty` makes a Pod without waiting containers `CLEAR`.

TIP: In a StackPack, put a long expression in its own file and include it without templating, for example `selector: "{{ include "./monitors/pods-in-waiting-state/selector.cel" "identity" }}"`.
