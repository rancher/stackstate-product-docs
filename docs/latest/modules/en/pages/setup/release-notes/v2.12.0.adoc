== Resource naming changes

Selected Kubernetes resources now use fixed `suse-observability-*` names instead
of names derived from the Helm release or fullname settings. Some resources are
renamed even when using the default release name.

* *Argo CD:* Enable pruning before upgrading, or sync with pruning. Otherwise,
  obsolete PDBs can block node drains, ServiceMonitors can duplicate scraping,
  and old Deployments can keep running the previous version. `PruneLast=true`
  does not enable pruning.
* *External references:* Update scripts and manifests that reference renamed
  resources, including the UI Service. This particularly affects installations
  using custom release names or fullname settings.
* *Upgrade interruptions:* Resource replacement and Pod restarts can temporarily
  interrupt the UI, connections and metrics collection. With backups enabled,
  the first upgrade also restarts the affected VictoriaMetrics and ClickHouse
  Pods, which can interrupt metrics and trace storage availability.
  Restart any active replication check after upgrading.
* *Interrupted upgrades:* Check for obsolete resources belonging to your
  installation and remove them individually. Preserve storage, credentials and
  configuration still referenced by Pods.

Bundled components now use the platform's connections. If you customized any of
these settings, review them before upgrading; saved values are also ignored:

[cols="1,2",options="header"]
|===
| Setting | New behavior

| `kubernetes-rbac-agent.url` / `clusterName`
| Use the local router and release name. Explicit `global.url.fromSecret` / `global.clusterName.fromSecret` still take precedence.

| `victoria-metrics-{0,1}.backup.overrideS3Endpoint` / `awsSecrets`, `clickhouse.backup.s3.endpoint` / `secretName`
| Use platform backup storage and credentials. Configure these through `backup.storage.backend` and `global.s3proxy.credentials`.

| `anomaly-detection.stackstate.instance`
| Use the local router.
|===

Collector `extraEnvs` can no longer override `MY_POD_IP`, `K8S_NODE_NAME`,
`API_URL` or `INTAKE_URL`, or `GOMEMLIMIT` when generated by the chart.

Existing persistent volumes and data are preserved. No storage migration is
required.

== Monitor Silencing

Silencing lets you mute a monitor result on a component during a known issue or maintenance window. The monitor keeps evaluating health, and the result stays visible.

* *Silencing Rules:* Mute a result from the monitor details. Add a note and a duration. The rule expires automatically.
* *Notification Control:* By default, muted results do not trigger notifications. Optionally, get notified when silencing changes.
* *Muted Filter:* Find muted components with `muted = true` in the advanced topology filter.

For more information, see xref:use/alerting/silencing.adoc[Silencing].

== New Features & Enhancements

* *Agent Secret Management:* The SUSE Observability Agent Helm chart now supports sourcing the cluster name and receiver URL directly from existing Kubernetes Secrets, simplifying GitOps workflows and enhancing credential security.

== Bug Fixes

* *SUSE AI StackPack Topology:* Fixed a regression where the SUSE AI StackPack failed to render OpenTelemetry-based topology relationships.
* *Show Topology Action:* Fixed a rendering issue with the *Show Topology* button inside the Related Resources drawer.
* *Notification Email Logging:* Fixed an issue where the email notification client failed to log error messages during delivery failures.
* *CPU Throttling Monitor:* Adjusted the CPU Throttling monitor evaluation window to inspect the last 5 minutes of data, preventing false positives caused by brief, momentary spikes in activity.
* *Self-Monitoring Metrics:* Fixed an issue where opening the same topology view across multiple browser tabs or sessions caused self-monitoring metrics (such as topology stream and WebSocket viewer counts) to intermittently drop from endpoint scrapes.
